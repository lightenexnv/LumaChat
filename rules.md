# Luma — Engineering Rules & Constraints for Coding AI

These rules are strictly binding for any engineer, subagent, or autonomous coding AI working on the Luma codebase. 
**VIOLATIONS OF THESE RULES WILL CAUSE IMMEDIATE REJECTION OF PRs OR CRITICAL SYSTEM FAILURES.**

---

## 1. Zero Capacitor & Zero WebView Policy
- **Rule 1.1**: Native iOS and Android apps MUST be real, first-class native applications.
- **Rule 1.2**: Under NO circumstances will Capacitor, Cordova, Ionic, React Native, Flutter, or WKWebView wrappers be introduced to implement core chat, calling, or settings screens.
- **Rule 1.3**: The iOS app MUST be written in pure Swift and SwiftUI.
- **Rule 1.4**: The Android app MUST be written in pure Kotlin and Jetpack Compose.
- **Rule 1.5**: The Web app MUST be written in modern React 19 and TypeScript.

---

## 2. No Mock Code, Fake SDP, or Dummy Placeholders
- **Rule 2.1**: NEVER generate hardcoded dummy SDP strings (e.g. `127.0.0.1` or fake session descriptions). All WebRTC offers, answers, and ICE candidates MUST be generated by a real WebRTC PeerConnection engine (`google-webrtc` / WebRTC framework).
- **Rule 2.2**: NEVER create non-functional placeholder buttons (e.g. attachment buttons that do nothing, dummy audio toggles). Every button shown to the user must be backed by working logic.
- **Rule 2.3**: Do NOT claim a feature is complete until it has been implemented and verified.
- **Rule 2.4**: Do NOT swallow errors with empty catch blocks (`catch {}` or `try?` without logging/handling). Always log errors clearly and provide user-facing feedback when appropriate.
- **Rule 2.5**: The **Fake YouTube reCAPTCHA Gateway Screen** (`GatewayScreen.tsx` / `gateway.ts`) MUST be preserved **100% identically** in the new version. The decoy YouTube mobile top bar, "Open App" behavior, Google reCAPTCHA v2 "I'm not a robot" step 1 checkbox with spinner, distorted cursive captcha canvas step 2 with tangled red squiggles and slate-blue graffiti font, audio speech button, and the secret unlock passphrase **`gune`** MUST be included with exact visual and behavioral parity.


---

## 3. Strict Cross-Platform Protocol Compatibility
- **Rule 3.1**: Web, iOS, and Android MUST use the EXACT same data schemas in Firestore and Realtime Database.
- **Rule 3.2**: E2EE Key Derivation must remain 100% interoperable:
  - PBKDF2 with SHA-256
  - 120,000 iterations
  - Salt: exact UTF-8 bytes of `luma:<conversationId>`
  - Key output: AES-GCM 256-bit key
- **Rule 3.3**: File and media attachments MUST use the identical binary payload structure:
  - First 12 bytes: IV (Initialization Vector)
  - Remaining bytes: AES-GCM Ciphertext + 16-byte authentication tag
  - Storage path: `conversations/{conversationId}/{messageId}/payload.bin`
  - Storage Content-Type: `application/octet-stream` (required by Firebase Storage Security Rules)
- **Rule 3.4**: Incoming call notification schema in RTDB `/incomingCalls/{calleeId}/{callId}` MUST include all 7 required fields (`callId`, `callerId`, `calleeId`, `kind`, `callerProfile`, `createdAt`, `state: "ringing"`), otherwise database validation rules will reject the write.

---

## 4. Architectural Boundaries & Decoupling
- **Rule 4.1**: Do NOT build monolithic files. The previous 6,346-line `App.tsx` is forbidden.
- **Rule 4.2**: Separation of Concerns:
  - Keep UI components purely presentation-focused.
  - Encapsulate all WebRTC logic in dedicated `WebRTCClient` / `WebRTCService`.
  - Encapsulate all signaling in dedicated `SignalingService`.
  - Encapsulate all cryptographic operations in `CryptoService`.
  - Encapsulate audio management and session routing in `AudioManager` / `SoundManager`.
- **Rule 4.3**: State management must follow Unidirectional Data Flow (UDF).

---

## 5. Security & Secrets Management
- **Rule 5.1**: NEVER commit sensitive credentials, API secret keys, private keys, or TURN server passwords to git repositories or public documentation.
- **Rule 5.2**: All documentation referencing credentials must mask them (e.g., `AIzaSy...`, `turn:****`).
- **Rule 5.3**: Sensitive runtime credentials must be loaded via `.env.local` (Web), `.xcconfig` / Secrets.plist (iOS), or `local.properties` (Android).
- **Rule 5.4**: Always adhere to Firebase Security Rules. Never bypass security rules using administrative service accounts in client apps.

---

## 6. Continuous Integration & Xcode Build Safety
- **Rule 6.1**: iOS builds MUST succeed in GitHub Actions runners (`macos-14`, Xcode 15.4 / 16.0) with zero compilation errors and zero signing failures when `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO`.
- **Rule 6.2**: Never use deprecated APIs that cause hard compile breaks (e.g. modifying read-only `CXProviderConfiguration.localizedName` or violating Swift Concurrency / Sendable boundaries).
- **Rule 6.3**: Always package the output archive into an installable IPA (`build/Luma.xcarchive/Products/Applications/Luma.app` -> `Payload/` -> `Luma.ipa`).

---

## 7. User-First Quality Rule
- **Rule 7.1**: When faced with a tradeoff between technical convenience and user experience, prioritize the experience that "simply works" for the person holding the device.
- **Rule 7.2**: Never conceal technical limitations. When 4G/LTE bandwidth drops, degrade gracefully to audio-only rather than freezing or crashing the call.
